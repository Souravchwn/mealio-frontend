# Module 14 — Database Schema

## Overview

Postgres via Supabase. ORM: Prisma v7 with `@prisma/adapter-pg`. All models use `@map()` for snake_case DB column names.

**Schema file:** `prisma/schema.prisma`
**Migration SQL:** `MIGRATION.sql` (idempotent, run in Supabase SQL Editor)
**Regenerate client after changes:** `npx prisma generate`

---

## Models

### `Mess`

Central entity. One mess = one shared living group.

```
id              String   @id @default(uuid())
name            String
inviteCode      String   @unique           // "MESS-XXXX" format
cutOffTime      DateTime @db.Time          // stored as 1970-01-01T{HH:MM}Z
estimatedMonthlyBudget  Decimal?
isActive        Boolean  @default(true)
createdAt       DateTime @default(now())

// Relations
members         Member[]
expenses        Expense[]
dailyLogs       DailyLog[]
messMonths      MessMonth[]
telegramGroups  TelegramGroup[]
mealConfigs     MealConfig[]
memberships     MessMembership[]
auditLogs       AuditLog[]
```

---

### `Member`

One row per user. A user belongs to exactly ONE primary mess (messId). Additional messes via `MessMembership`.

```
id              String   @id @default(uuid())
messId          String?                    // primary mess (FK → Mess)
email           String   @unique
name            String
phone           String?
passwordHash    String
role            String   @default("MEMBER")  // ADMIN|MANAGER|MEMBER|GUEST
telegramUid     BigInt?  @unique            // Telegram user ID (bigint!)
telegramLinked  Boolean  @default(false)
isActive        Boolean  @default(true)
isGuest         Boolean  @default(false)
guestFrom       DateTime? @db.Date
guestUntil      DateTime? @db.Date
createdAt       DateTime  @default(now())

// Relations
mess            Mess? @relation(fields: [messId], references: [id])
dailyLogs       DailyLog[]
expenses        Expense[]
memberships     MessMembership[]
mealPreferences UserMealPreference[]
```

**Key notes:**
- `telegramUid` is `BigInt` — Telegram user IDs exceed JavaScript's safe integer range. Always use `BigInt(uid)` when writing.
- `messId` can be null for SYSTEM_ADMIN accounts.

---

### `DailyLog`

One row per member per day. The core of the meal tracking system.

```
id              String   @id @default(uuid())
memberId        String                     // FK → Member
messId          String                     // FK → Mess
logDate         DateTime @db.Date          // UTC midnight, e.g. 2026-04-13
breakfastCount  Int      @default(1)       // 0=off, 1=normal, 2+=extra
lunchCount      Int      @default(1)
dinnerCount     Int      @default(1)
guestCount      Int      @default(0)
frozen          Boolean  @default(false)   // true after month is closed
isOverride      Boolean  @default(false)   // true if manually changed
overrideType    String?                    // USER|ADMIN|SYSTEM|null
toggledAt       DateTime?
createdAt       DateTime @default(now())

@@unique([messId, memberId, logDate])     // one log per member per day
```

**Key design:**
- Integer counts replaced boolean flags. 0=off, 1=normal, 2+=extra portions.
- `frozen: true` blocks all further modifications (set by `closeMonth()`).
- `isOverride: false` + `overrideType: null` = auto-generated by cron.
- `isOverride: true` + `overrideType: 'USER'` = member toggled it.
- `isOverride: true` + `overrideType: 'ADMIN'` = admin edited it.

### `MealConfig`

Per-meal, per-mess cutoff configuration. Replaces the old single `mess.cutOffTime` for per-meal granularity.

```
id          String   @id @default(uuid())
messId      String                     // FK → Mess
mealType    String                     // BREAKFAST|LUNCH|DINNER
enabled     Boolean  @default(true)
cutoffTime  DateTime @db.Time          // stored as 1970-01-01T{HH:MM}Z
maxCount    Int      @default(10)      // max portions per member

@@unique([messId, mealType])           // one config per meal per mess
```

**Seeded on mess creation:** 3 rows — BREAKFAST 08:30, LUNCH 13:00, DINNER 21:00.

---

### `UserMealPreference`

Defaults for each member's meals. 6 rows per member = 3 meals × 2 day types.

```
id            String   @id @default(uuid())
memberId      String                     // FK → Member
messId        String                     // FK → Mess
mealType      String                     // BREAKFAST|LUNCH|DINNER
dayType       String                     // WEEKDAY|WEEKEND
enabled       Boolean  @default(true)
defaultCount  Int      @default(1)       // what count to restore on /meal on

@@unique([memberId, messId, mealType, dayType])
```

**Missing rows = enabled=true, defaultCount=1.** The code handles missing rows gracefully.

### `Expense`

A bazaar expense logged by a manager.

```
id              String   @id @default(uuid())
messId          String                     // FK → Mess
addedBy         String                     // FK → Member (who logged it)
amount          Decimal
category        String                     // ExpenseCategory enum value
description     String   @default("")
expenseDate     DateTime @db.Date
yearMonth       String                     // "YYYY-MM" (denormalized for fast month queries)
createdAt       DateTime @default(now())
```

### `MessMonth`

Snapshot of a closed month. Created by `closeMonth()`.

```
id              String   @id @default(uuid())
messId          String                     // FK → Mess
yearMonth       String                     // "YYYY-MM"
isClosed        Boolean  @default(false)
closedAt        DateTime?
mealRate        Float    @default(0)
totalExpense    Float    @default(0)

@@unique([messId, yearMonth])
```

---

### `LedgerEntry`

Financial accounting entries. Created on month close.

```
id              String   @id @default(uuid())
messId          String                     // FK → Mess
messMonthId     String                     // FK → MessMonth
memberId        String                     // FK → Member
entryType       String                     // DEDUCTION | CARRY_FORWARD
amount          Float                      // negative for deductions
note            String   @default("")
createdBy       String                     // FK → Member (admin who closed)
createdAt       DateTime @default(now())
```

**`DEDUCTION`**: `amount = -(memberMeals × mealRate)` — logged in the closing month.
**`CARRY_FORWARD`**: `amount = contributed - mealCost` — balance carried to next month.

---

### `TelegramGroup`

Links a Telegram group chat to a mess.

```
id          String   @id @default(uuid())
chatId      String   @unique                // Telegram chat ID (string, can be negative)
messId      String                          // FK → Mess
chatName    String   @default("")
timezone    String   @default("Asia/Dhaka")
isActive    Boolean  @default(true)
createdAt   DateTime @default(now())
```

Only one active group per mess is used. Timezone from here drives all time calculations.

---

### `MessMembership`

Enables multi-mess support. A user can be in multiple messes with different roles.

```
id          String   @id @default(uuid())
memberId    String                          // FK → Member
messId      String                          // FK → Mess
role        String                          // ADMIN|MANAGER|MEMBER
isActive    Boolean  @default(true)
createdAt   DateTime @default(now())

@@unique([memberId, messId])
```

---

### `AuditLog`

Immutable log of all admin actions.

```
id          String   @id @default(uuid())
messId      String                          // FK → Mess
actorId     String                          // FK → Member (who did it)
action      String                          // TOGGLE_MEAL|ADD_EXPENSE|CLOSE_MONTH|etc.
targetTable String?                         // 'daily_logs', 'expenses', etc.
targetId    String?                         // ID of the affected row
oldValue    Json?
newValue    Json?
createdAt   DateTime @default(now())

// Relations
actor       Member   @relation(fields: [actorId], references: [id])
mess        Mess     @relation(fields: [messId], references: [id])
```

**Querying with actor name:**
```typescript
prisma.auditLog.findMany({
  select: {
    // ...other fields
    actor: { select: { name: true } }  // joins Member.name
  }
})
// entry.actor?.name ?? 'System'
```

## Common Query Patterns

### Get today's log for a member
```typescript
await prisma.dailyLog.findFirst({
  where: { memberId, messId, logDate: new Date(`${date}T00:00:00.000Z`) }
})
```

### Get all logs for a month
```typescript
const { start, end } = monthRange(yearMonth)
await prisma.dailyLog.findMany({
  where: { messId, logDate: { gte: start, lte: end } }
})
```

### Upsert a DailyLog (idempotent create-or-update)
```typescript
await prisma.dailyLog.upsert({
  where: { messId_memberId_logDate: { messId, memberId, logDate } },
  create: { ... },
  update: { ... },
})
```

### Get mess timezone
```typescript
const mess = await prisma.mess.findUnique({
  where: { id: messId },
  select: {
    cutOffTime: true,
    telegramGroups: { where: { isActive: true }, select: { timezone: true }, take: 1 }
  }
})
const timezone = mess?.telegramGroups[0]?.timezone ?? 'Asia/Dhaka'
```

## Schema Change Procedure

1. Edit `prisma/schema.prisma`
2. Run `npx prisma generate` to update the Prisma client
3. For production: add the SQL change to `MIGRATION.sql` as an idempotent `ADD COLUMN IF NOT EXISTS` or `CREATE TABLE IF NOT EXISTS`
4. Apply `MIGRATION.sql` in Supabase SQL Editor before deploying
5. For local dev: `$env:DIRECT_URL="..."; npx prisma db push --accept-data-loss`

## `@db.Time` Fields — Important

Prisma stores `@db.Time` columns as a `DateTime` with date `1970-01-01`. When reading:
```typescript
// Convert to HH:MM string:
cutoffTime.toISOString().slice(11, 16)   // "21:00"
```

When writing:
```typescript
// Convert HH:MM string to DateTime:
new Date(`1970-01-01T${hhmm}:00.000Z`)
```

This pattern appears in: `Mess.cutOffTime`, `MealConfig.cutoffTime`, all cutoff-related code.
